## Problem Statement

旧项目是「代码学习辅导」，和 Cursor 等 coding agent 相比没有使用理由。真正已存在、且你每天会碰到的资产，是 `douyin-fav-transcribe`：登录采集收藏/喜欢、faster-whisper 转写、Obsidian markdown 落库。

要做的不是再造一个转写器，而是 **对着已有转写的阅读 Agent**：划线、自定义提示词解释/总结、写入笔记、豆包式追问、用工具做检索与分类、用 `memory.md` 记住习惯。第一版只做抖音。

产品是融合体，不对标成「像某个 App」。对面试说的那句话：**交互学聊天产品，上下文是我的本地收藏转写，循环在 Node，脏活在 Python。**

## Constraints

- 简历栈：Vue3 + TypeScript + Node。Agent **循环必须在 Node**，否则「我做了 agent」会被问穿。
- Python 保留：采集、登录态、抽音频、Whisper、写 md、必要时的中文向量检索。
- v1 要能演示：划线弹窗 + SSE 流式 + 追问 + **Jev 分类** + **memory.md 习惯追问**（薄但真跑，不是 TODO）。
- 旧亮点：SSE 必留。Markdown-it / Shiki / Worker / 首 token 监控 **不为简历硬留**；只在 Agent UI 渲染长转写会卡时再上。
- 不做代码 Diff / 代码选中解释。
- 交付面：**同一份内容，Markdown 给 Obsidian 源码阅读；HTML/Web 给交互与 Agent。** AI 写代码、时间盒不作为砍范围的理由。

## Dual surface: Markdown + HTML（调研结论：能做）

**能实现。** 但两条入口的能力不一样，不要假装「一个 HTML 文件 = 完整 Agent」。

| 入口 | 用户怎么打开 | 能做什么 | 做不到 / 坑 |
|---|---|---|---|
| `.md` 在库里 | Obsidian 默认阅读/编辑 | 可移植、可搜索、可 git、符合现有 `抖音收藏/*.md` | **没有你的 Vue 划线弹窗**；Obsidian 预览用它自己的渲染器，**不会跑你的 Web Worker** |
| Agent UI（推荐主交互） | 浏览器打开 `http://127.0.0.1:<port>`，或 Obsidian **Custom Frames / 核心 Web Viewer** 嵌同一 URL | 完整 Vue：划线、SSE、工具轨迹、Jev 确认、memory 编辑。**Web Worker 可用**（普通页面 origin） | 必须本机 Node 在跑；手机 Obsidian 嵌 localhost 基本不行 |
| 库内 `.html` | 社区插件 Local Web Page Viewer / Local HTML Embed（iframe `srcdoc`） | 可把「阅读页」嵌进笔记；静态高亮展示可行 | Obsidian CSP：外链 CSS/script、对 localhost 的 `fetch` 常被卡。**不要把整份 Vite App 复制进 vault 当静态站** |

推荐契约（B 路径下的双格式）：

1. **源真相永远是 Markdown**（frontmatter：`folders`、`liked`、`video_id`、高亮 offset 列表）。用户随时在 Obsidian 里读原文。
2. **Agent 永远打活服务**（Node）。Obsidian 只是第二个「浏览器壳」，不是第二套后端。
3. 每条视频可附一张很薄的 callout：说明「打开 Web Viewer → 本机阅读页」，避免和正文抢渲染。
4. 高亮写回 md，只读 md 的人也能看到摘录；完整弹窗只在 Web 入口。

**Web Worker 放哪：** 只放 Agent UI（浏览器或 Custom Frame）。解析超长转写、避免输入框卡顿时才值得。Obsidian 原生预览路径 **不要** 塞 Worker。

## Landscape (generalized)

- 常规产品是「再做一遍入库 + RAG」（OpenNote：Node + Python Whisper；douyin-rag：FastAPI + Chroma）。
- 划线弹窗是成熟 UX（解释/总结/自定义提示词 + 追问）。
- Node 本地 RAG 已有，中文质量仍常走 Python embedding。

**EUREKA:** 不要把 ingest 当产品。你已经有 ingest。差异在阅读层的工具循环、人机中断、以及 md/Web 双入口。

## Premises

1. v1 只做抖音收藏/喜欢转写库。
2. Node 拥有模型+工具+SSE+中断；Python 是工人 + 可选中文 retrieve。
3. v1 必有：阅读、划线、流式、追问、Jev 分类、memory.md；RAG 作为 retrieve 工具，零命中必须承认。
4. 双入口 md + 活 HTML/Web；静态 html 进库只做辅助。
5. 停下来问人：Jev 低置信/两分类接近；写笔记目标文件含糊；RAG 空或来源互斥还要当事实；改 memory 永久偏好；任何改抖音账号的操作。解释/总结/追问默认不停。

## Approaches Considered

### Approach A: 最小能用环
拒因：用户要更完整运行时，且不担心实现量。

### Approach B: 理想运行时（选定）
显式会话状态、工具注册表、HITL 中断、转写完成触发切块/索引、Jev 可单条也可批、memory 定期从行为日志编译、md 与 Web 双写策略如上。

### Approach C: MCP 薄 UI
拒因：前端岗作品集过弱。

## Recommended Approach

**B + 双表面契约。**

### Node（agent 循环）

- 会话状态机：`idle | streaming | tool | hitl | followup`。
- 工具：`explain_selection`、`summarize_selection`、`add_to_notes`、`classify_item`（Jev：folder + confidence）、`retrieve_vault`、`read_memory`、`propose_memory_patch`（写永久偏好必须 HITL）。
- SSE：token、tool_call、tool_result、hitl_request、followup_suggestions。
- 前端展示工具名/参数/结果（面试工件）。
- 划线动作提示词可编辑。

### Python（工人）

- collector / whisper / 写 md **不迁 Node**。
- 转写成功：切块、embedding、更新索引。
- `POST /retrieve` 返回 `{path, title, span, score}`。

### Vue

- 左：转写正文（可选 md-it；卡再 Worker+Shiki）。
- 浮层：划线工具条。
- 右：对话、追问芯片、HITL 卡片（已有夹 / 新建 / 跳过）。
- 设置：`memory.md`、动作提示词、置信度阈值。

### 简历怎么讲

- 「Agent 在 Node」= 循环、工具、中断、流式，不是 Whisper。
- 「Python」= ASR 与中文检索。Java 团队同样会拆编排 vs 模型服务。
- 「双格式」= md 可离线读；Web 是同一 Agent 的壳，不是两份漂移正文。

## Success Criteria

- 真实转写：划线 → 自定义提示词流式解释 → 追问两条 → 入笔记写回 md。
- Jev：高置信写 folders；低置信三选并落盘。
- `memory.md` 可编辑；习惯追问来自该文件；改永久偏好先问人。
- retrieve 引用标题+片段；空库说找不到。
- 桌面 Obsidian Web Viewer 能开本机阅读页；库里能开对应 `.md`。

## The Assignment

用 Obsidian **Web Viewer** 或 **Custom Frames** 打开 `http://127.0.0.1:5173`。嵌入页点击、输入、markdown-it 转 HTML 已通过。Agent 与转写服务必须同时在本机跑。
