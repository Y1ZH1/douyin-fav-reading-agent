# 收藏阅读 Agent：三栏、对话怎么挂笔记、提示词和记忆怎么分工

## 给读这份说明的人

这是给本机自己用的阅读工具，不是再做一个通用聊天窗口。材料是已经转写好的抖音笔记（Obsidian 里的 markdown，下面叫笔记库）。聊天记录存在浏览器里，不写进笔记库。

用户已确认下面这版。实现时按 P0 验收。P1 写在同一份里，但不挡 P0。

## 打开之后长什么样（P0）

最左边只有两个切换：

- 「对话」：每一项两行，上面是对话标题，下面是视频名。
- 「收藏夹」：第一层是收藏夹，第二层是里面已经转写的视频。没归类的单独一组。

中间是正在看的那篇转写。正文用现有的 markdown 转 HTML。顶上能看到这篇笔记在电脑上的路径，可以复制。在 Windows 上可以打开它所在的文件夹。中间还能列出「和这篇笔记有关的对话」，点一下就切过去。

右边是这场对话里的消息：流式回答、划线后的解释和总结、追问、需要人确认的卡片。

不要再出现现在这种四栏：最左空会话、第二列又是一份视频列表。个人简介、代码差异、代码分析从导航里拿掉。设置留下。这些旧页面的源码先别删。

## 对话怎么建、什么时候带上笔记（P0 + P1）

从某篇笔记里点「新建对话」：这场对话默认带着这篇转写。模型能读到的是笔记 id、路径，加上正文，正文最多大约 8000 字。后面的内容不会自动整篇塞进去。

同一场对话里，用户可以再手动钉上别的笔记。

单独新建一场对话（不从笔记进来）：默认什么笔记都不带。只有用户明确说要去笔记或库里找，才去检索。检索到的结果只给这一轮用，不会自动钉进对话。用户勾选之后才钉上。独立新建和「先列出候选再勾选」属于 P1，P0 必须先做对的是「从笔记新建、默认带上这一条」以及「没说要找就不检索」。

检索没有结果时，直接说没找到，不要编出处。

## 提示词和 memory.md（P0）

用户自己改的是划线之后的动作，例如解释、总结。这些放在设置里，划线解释和总结要走用户写的那份提示词。

memory.md 由 Agent 维护，用来记习惯。用户可以看。真要改这份文件，必须先确认再写入。主界面不要把它当成用户每天编辑的说明书。

## 存哪（P0）

对话继续用现有的浏览器存储（IndexedDB 那套会话）。每场对话要能记下标题、视频名、钉上了哪些视频 id。刷新之后对话还在。不要把对话写成笔记库里的 markdown。

笔记库只放转写和 Agent 在得到确认后写入的划线、分类、memory.md。

## 检索的后一步（P1，不挡 P0）

现在已有全文检索。P1 可以加可选的向量检索，在 Python 里做。默认仍走全文检索。向量失败就退回全文检索。不要用向量换掉全文检索。

## Obsidian（不做插件）

不写 Obsidian 插件，也不把网页打包进笔记库。Obsidian 里直接打开 http://127.0.0.1:5173 即可。使用前本机要同时开着转写服务（8899）和 npm run dev（5173 与 3001）。

## 怎样算做完

P0：

1. 最左只有「对话」和「收藏夹」，导航里没有个人简介、差异、代码分析。
2. 收藏夹能展开到视频。点开后中间是转写的 HTML，顶上有可复制的路径。
3. 在这篇笔记上新建对话后，右边能聊，请求里带上这条笔记的截断正文。左边对话是两行：标题和视频名。
4. 中间能列出并切换这篇笔记关联的对话。
5. 用户没说要找内容时，不去检索。检索命中不会自动钉上。
6. 设置里改解释或总结提示词后，划线动作用这份提示词。改 memory.md 仍要确认。
7. 刷新后对话还在。

## 不要做

- Obsidian 插件，或把整站拷进笔记库
- 把聊天记录写成笔记
- 删掉旧的差异、解释、简介源码（只从导航隐藏）
- 用 Agent 去取消收藏或改抖音账号
- 用向量替换全文检索
- 每一句话都自动搜整库
